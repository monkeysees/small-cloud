# Status and logs

[Issue #11](https://github.com/monkeysees/small-cloud/issues/11) provides diagnostics through the existing authenticated CLI/API. An app's creator and its workspace administrator can inspect status, operation failures, and build/runtime logs. Other creators and ordinary members receive `NOT_FOUND`. Diagnostic authority does not permit opening someone else's creator-only app or reading secret configuration. Platform-administrator status alone adds no workspace permission.

```bash
small-cloud status example --json
small-cloud logs example --source build --limit 100 --json
small-cloud logs example --source runtime --since 2026-09-09T00:00:00Z --json
small-cloud logs example --source build --deployment d_DEPLOYMENT --json
small-cloud logs example --source runtime --cursor CURSOR_FROM_PREVIOUS_RESPONSE --json
```

Snapshots are chronological, at most 1 MiB including the response envelope, and at most 1,000 entries (`--limit` defaults to 100). A cursor continues the original snapshot, excluding newly ingested records, even if another build becomes the latest. Cursors belong to the requesting identity, app and source, expire after ten minutes, and require authorization on every page. At most 1,000 outstanding cursors are retained; older ones can expire sooner under pressure. `--cursor` and `--since` are mutually exclusive. `--deployment` applies only to build logs; omission selects the latest build. No streaming CLI mode or debug archive is provided. Terminal controls are escaped in both human and JSON output.

Logs expire seven days after ingestion. Each build retains at most 10 MiB; each app retains at most 50 MiB of runtime logs across all deployments. Overflow evicts oldest complete records. Records are at most 16 KiB including their encoded JSON metadata; long records end in `[truncated]`. `truncated`, `dropped_bytes`, `oldest_available_at` and `next_cursor` distinguish permanent loss from pagination. `dropped_bytes` counts known shortening and encoded records removed by age or volume, not unread pages. `collection_interrupted` additionally flags possible unmeasurable loss after a collector restart, transport disconnect or container stop. No byte count is invented for such gaps. Counters cover the stream's history, including expired records.

Known database URLs/passwords, configured confidential platform values and registered app values are redacted **before persistence and shortening**, including values split across input chunks. Runtime framing can split or combine records while the collector holds a possible secret prefix; multiline values are also matched after Docker removes newline delimiters. Redaction-only values are encrypted with a separate root-owned key. Active values remain available; replaced values expire seven days after their last possible runtime use, with a one-minute maintenance margin. Unreconciled candidates remain possible users. The registry has no readback API. Creator secret configuration remains #12; it must register values before runtime handoff and retain replaced values through this registry. App deletion in #13 must remove its logs, counters, cursors and encrypted redaction rows together.

Literal redaction is **not a guarantee against disclosure by app code**. Encoding, transforming or deliberately transmitting a value can evade it. Logs may contain app-chosen content; administrative log access does not create an HTTP route into private app content. Direct root access remains a separate operator trust boundary.

## Collection and upgrades

The unprivileged identity service reads only redacted records on the existing EU control disk. A separate root collector receives runtime syslog through a pinned SSH forward between Unix sockets on the German control/runtime hosts. Both sockets are root-only; no TCP log listener or app-accessible management route is added. The runtime uses Docker's blocking syslog driver with `cache-disabled=true`, preventing Docker's otherwise automatic unredacted disk cache. Backpressure can slow a logging-heavy app. Disconnections can lose output and are explicitly marked; this is bounded diagnostics, not a durable audit service.

Build stdout is streamed over SSH from the isolated EU builder into the publishing worker's redactor. Builders receive no redaction secrets. Their execution stdout and daemon output are not saved locally; the product controller does not create a raw `build.log` copy. BuildKit's separate step-size/rate clipping is disabled so the platform can apply its agreed volume bound and report actual losses. The root operator `infra/remote.py build` interface still provides its separately bounded `build.log` artifact unless `--stream-build-log` is selected; product publishing always selects streaming.

Drain accepted deployments, stop the publishing worker, and install the package, `infra/remote.py`, `infra/builder/worker.py`, `infra/builder/run.sh` and `infra/runtime/sandbox.py` together. Start the upgraded identity service to create diagnostic tables. Install and enable [small-cloud-diagnostics.service](small-cloud-diagnostics.service), then start publishing. Both root processes use `/srv/small-cloud/secrets/diagnostics.key` (0600 under the existing root-only secret directory). Preserve this key while retained encrypted values exist. No new dependency or cloud resource is required.

The root processes seed redaction from existing encrypted database credentials, `/etc/small-cloud/identity/server.json`'s `google_client_secret`, and the control's `/root/.config/small-cloud/secrets/hetzner-token`. Publishing configuration may specify `identity_config`, `redaction_files` (exact files containing a confidential value) and `redaction_key` for a different installation. Missing or unsafe configured files fail closed. The collector refreshes platform values and performs retention maintenance every 30 seconds even when nobody reads logs or publishes. Snapshot reads and ingestion also prune expired records.

On worker startup, previous bounded build-log columns are imported with their recorded finish time (creation time if unfinished), re-redacted, securely cleared and removed. Already expired legacy logs are removed. This migration cannot undo disclosure that occurred before this upgrade. Historical raw staging diagnostics from the previous implementation require task-scoped removal after import; existing artifact timers continue to clean source/image staging independently. SQLite securely deletes removed records and reuses freed pages; file allocation can retain its high-water size without retaining expired content.

Existing containers created with logging disabled need a controlled replacement using their retained image, same database/environment, same deployment tag and normal candidate/readiness/promotion boundary. Container logging options cannot be changed in place. Preserve app URL, data and sharing. Until replacement, their prior runtime output is unavailable. New publications pass `--deployment` to the sandbox automatically; the existing root-only sandbox probe interface without that flag still discards output.

If the collector fails, inspect service state and the two root-only sockets, restore the pinned SSH connection, and verify a new app log marker through the CLI. Do not enable Docker's local cache or raw journald output to debug confidential app streams. Services suppress raw stdout/stderr and core dumps. Missing historical output cannot be recovered.

Implementation references: [Docker syslog options](https://docs.docker.com/engine/logging/drivers/syslog/) and [Docker dual logging/cache behavior](https://docs.docker.com/engine/logging/dual-logging/).
