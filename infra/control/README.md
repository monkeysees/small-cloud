# Control host

`bootstrap.sh` configures a dedicated Ubuntu 24.04 amd64 host after the infrastructure provisioner has assigned private address `10.42.0.2`. Run it as root with this directory present. It installs distribution packages, persists PostgreSQL, source, registry, encrypted credentials and reserved application-log storage under `/srv/small-cloud`, and serves a closed HTTP 503 gateway at `https://small-cloud.monkeysees.one`. Re-running preserves data and credentials, restarts services and reapplies the closed gateway. Do not run it against a future authenticated production gateway without reviewing that replacement.

The host disk survives service/container restart, not host deletion. No automatic host replacement or durable-data promise is provided. Caddy obtains and renews public certificates automatically; the explicit DNS record must point directly to the host and public TCP 80/443 must remain reachable for ACME. Its state is `/srv/small-cloud/caddy`. No app ingress or login bypass exists in this bootstrap; #4/#5 must replace the 503 only after authenticated gateway routing passes its acceptance gate.

PostgreSQL 16 accepts encrypted SCRAM connections from runtime host `10.42.0.3` and local TCP only. Administration uses the local Unix socket with OS-user `postgres` peer authentication. Provider firewalls must independently deny public 5432 and allow the runtime private host. Each app receives a non-owner, non-superuser role with own-database connect and public-schema create permissions. The administrator owns the databases; PUBLIC connection rights are removed from maintenance and app databases. The local PostgreSQL 18 probe in earlier hosting research is not evidence for this deployed PostgreSQL 16 configuration.

Provision a database using `sudo small-cloud-tool-database IMMUTABLE_APP_ID`. The JSON result contains only nonsecret identifiers, encrypted credential path and public CA path. Repeated calls recover the same password; the root-only lock serializes provisioning, and credentials are encrypted and fsynced before database creation so interrupted creation can be retried. A fresh role remains unable to log in until its database permissions are applied. The helper does not implement user-facing reset/delete workflows.

Use the root operator SSH connection to decrypt the returned file with `age --decrypt -i /srv/small-cloud/secrets/identity.age <encrypted-path>` directly into a trusted runtime controller's stdin. Never run that command with output attached to an operator transcript or pass credentials as arguments. The decrypted JSON contains `database_url`, `password`, `database`, `user`, and `tool_id`. The operator probe runner accepts a root-only environment file; keep it under `/run` and remove it immediately after container creation. Copy the nonsecret `/etc/small-cloud/database-ca.crt` to the runtime; the runtime harness adds it to a derived image without executing app code or mounting host directories. URLs require `sslmode=verify-full` with the private IP certificate pinned to this CA. The self-signed database certificate expires after one year; the operator must rotate it and redistribute the pin before expiration. This is separate from Caddy's automatic public-certificate renewal. The encryption identity and encrypted data are both on the trusted control host; encryption does not protect against control-host root compromise.

The registry listens only at `127.0.0.1:5000`. Use the [release handoff](../artifacts/README.md#release-handoff) for journaled publication, retention, retirement and private runtime import. Do not expose its unauthenticated listener on the private network or give builder/app code an operator SSH key. Source uploads and application secrets/logs have root-only reserved directories; their product APIs and per-app redaction remain publishing/logging work. Journald has 256 MiB persistent and 64 MiB runtime bounds and seven-day retention; PostgreSQL diagnostics rotate at 10 MiB/seven files when logrotate runs. These host diagnostic settings do not implement the product's stricter per-app log contract. Disk alerts and the new-work 10 GiB free-space guard cover growth alongside scheduled staging/release cleanup; unrestricted database growth still needs operator attention.

Before admission, run real runtime-host own-database write/read and cross-app/maintenance denial probes, verify public 5432 and registry denial, inspect actual service/package versions, verify the public certificate and renewal configuration, restart the host and repeat connectivity checks. This directory's syntax checks do not establish those live boundaries.
